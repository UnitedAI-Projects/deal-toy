# MCP OAuth sign-in implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let any active Mantel member connect an MCP client to `/mcp` by signing in and approving a consent screen. API keys keep working.

**Architecture:** The Worker's default export becomes a thin wrapper around `@cloudflare/workers-oauth-provider`'s `OAuthProvider`.

- **`/mcp`:** the protected API route. Its handler loads the member's current identity from the token's `{ email }` props.
- **API keys:** `resolveExternalToken` maps `mtl_…` keys to the same props through the existing `authenticateKey`.
- **Everything else:** the existing request handling, moved unchanged into the default handler. That now also serves a server-rendered consent page at `/authorize` and the **Connected apps** settings routes.

**Tech stack:**

- **Server:** Cloudflare Workers, D1, Workers KV (`OAUTH_KV`) and `@cloudflare/workers-oauth-provider` 1.2.4.
- **Tests:** Vitest with `@cloudflare/vitest-plugin`.
- **Web:** React 19 for the settings UI.

**Spec:** `docs/superpowers/specs/2026-11-05-mcp-oauth-design.md`

## Global constraints

- **Dependency:** `@cloudflare/workers-oauth-provider` pinned exactly at `1.2.4`, released 2026-10-22.
- **Tokens:** access tokens last 1 week (`accessTokenTTL: 604800`). Refresh tokens rotate and expire after 30 days without use (`refreshTokenTTL: 2592000`, `refreshTokenIdleTTL: 2592000`).
- **Scope:** one scope, `mantel` (`scopesSupported` and `requiredScopes`).
- **Endpoints:**
  - `authorizeEndpoint: "/authorize"`;
  - `tokenEndpoint: "/oauth/token"`;
  - `clientRegistrationEndpoint: "/oauth/register"`;
  - `apiRoute: "/mcp"`.
- **Resource:** `${env.APP_ORIGIN}/mcp`. `APP_ORIGIN` is a new var: `https://unitedai-deal-toy.ivan27chen.workers.dev` in production and `https://example.test` in tests.
- **Grant props:** exactly `{ email: string }` for OAuth grants and `{ email: string, keyId: string }` for API keys. `userId` is the member's email.
- **Who may connect:** any active member. Suspended or unknown members are refused, and what a token can do is exactly the member's current permissions.
- **Where tokens work:** OAuth tokens work only on `/mcp`. `/api/*` accepts only browser sessions, as today.
- **API keys:** keys still need `keys.use`. Its label becomes "API keys" everywhere it is shown. Existing key behaviour and messages are otherwise unchanged.
- **Security:** never commit secrets, and never write production D1 or Cloudflare resources without the owner's approval.
- **Attribution:** commit as `ichen27 <ivan27chen@gmail.com>`, with no AI attribution.
- **Before committing:** each task ends with `npm run format:check`, `npm run typecheck` and `npm test` passing.

## Review focus

1. **Hostile client metadata:** a client registers with a `client_name` containing HTML. The consent page shows it as text, and the redirect host shown is the one the code will actually be sent to. (Task 3, `consent page escapes client metadata`.)
2. **Session ends mid-consent:** the session expires or signs out between showing consent and pressing **Allow**. The POST re-checks the session and sends the person to sign in rather than authorising. (Task 3, `allow without a session does not authorise`.)
3. **Replayed approval:** a consent form is submitted twice or with a stale handle. The page shows a plain error, never a 500, and issues no second code. (Task 3, `a consent handle works once`.)
4. **Lost permission:** the member's level changes after connecting, for example from Maker to Demo. The tool list on the next request reflects the new level. (Task 3, `token follows level changes`.)
5. **Registration spam:** registration is flooded from one IP. `AUTH_LIMITER` answers 429. (Task 1, `client registration is rate-limited`.)

### Task 3: Consent screen and the full OAuth flow

**Files:**

- Create: `src/server/consent.ts`.
- Modify: `src/server/index.ts`, routing `/authorize` GET and POST to `consent.ts` before the assets branch.
- Test: `src/server/oauth.test.ts`, extended.

**Interfaces:**

- Consumes: `provider(env)` and `SCOPE` from Task 1. `safeNext` behaviour from Task 2, through the URL `/api/auth/google/start?next=<encoded /authorize?…>`. `authenticateBrowser` from `auth.ts`. `env.OAUTH_PROVIDER: OAuthHelpers`, which the provider injects into the default handler.
- Produces: `src/server/modules.d.ts` declares `interface Env { OAUTH_PROVIDER: import("@cloudflare/workers-oauth-provider").OAuthHelpers }`, because the provider injects this binding at run time.
- Produces: `export async function authorize(request: Request, env: Env): Promise<Response>`.
  - **GET:**
    1. `parseAuthRequest`. An `AuthorizationError` with `redirectTo` gives a 302 there; any other error renders an error page with status 400.
    2. Without a session, return a 302 to Google start with `next = pathname + search`. Suspended members see an explanation page with status 403 and no redirect. Detect them with `memberAccess`.
    3. `describeConsent` and `beginConsent`, then render the page with the consent headers.
  - **POST:**
    1. Re-authenticate the session. Without one, return a 302 to Google start with `next` taken from the form's `return_to` field, which is the original `/authorize?…`.
    2. If the form says `action=allow`:
       - call `approveConsent(request, handle, { scope: [SCOPE] })`;
       - then `completeAuthorization({ request: approved.request, userId: email, scope: [SCOPE], props: { email }, metadata: { clientName } })`;
       - return a 302 to `redirectTo` with `approved.headers`.
    3. If the form says `action=cancel`: `denyConsent`, and return its headers.
    4. An `AuthorizationError` from either renders the error page with status 400: "This approval expired or was already used. Start connecting again from your app."
- Produces: the consent page. It is a complete HTML document with no scripts, styled inline with Mantel's colours, and has:
  - **Title:** "Connect `<clientName>` to Mantel";
  - **Address line:** "It will return to `<redirectHost>`", followed by "(an app on this computer)" when `redirectIsLoopback`;
  - **Account line:** "Signed in as `<email>`";
  - **Access line:** "It will be able to use Mantel as you, with your current access level.";
  - **Form:** a POST to `/authorize` with hidden `handle` and `return_to`, and the buttons **Allow** (`name=action value=allow`) and **Cancel** (`value=cancel`).
  - **Escaping:** every interpolated string is escaped (`& < > " '`).
